# Публикация витрины

Подготовлена отдельная папка для новой Git-истории: рабочий репозиторий и его историю переносить нельзя. Публикация выполняется только после подтверждения владельца.

## Перед публикацией

1. Выполнить `npm test` и проверить точный список файлов ниже.
2. Просмотреть README, страницу, SVG и любой скриншот вручную. Проверка по шаблонам не гарантирует отсутствие всех чувствительных данных.
3. Создать отдельный пустой репозиторий для showcase. Не добавлять remote к производственному проекту ради этой публикации.
4. Добавлять только явно проверенные файлы. Не копировать `.git`, `.env`, базы, логи, реальные отчёты, конфигурацию интеграций и внутренние документы.
5. Проверить staged diff и список файлов перед первым коммитом. Не загружать архив рабочего проекта.
6. После публикации витрины добавить проверенный адрес GitHub Pages в README и в отклик. До этого не выдавать локальную страницу за опубликованную.

## Состав

- `README.md`, `PUBLISHING.md`, `.gitignore`, `package.json`, `FB-Autoload.html`
- `docs/engineering.md`
- `dist/index.html`, `dist/style.css`, `dist/app.js`, `dist/recovery.mjs`, `dist/launch-demo.mjs`
- `dist/assets/cover.svg`, `dist/assets/mark.svg`
- `scripts/preview.mjs`, `scripts/check-public.mjs`, `scripts/build-preview.mjs`
- `tests/recovery.test.mjs`, `tests/launch-demo.test.mjs`
- `.github/workflows/pages.yml`

GitHub Pages должен обслуживать **только `dist/`**. Страница использует относительные пути: она подходит и для корня домена, и для пути репозитория. Workflow `Verify and publish showcase` проверяет тесты, точный состав файлов и воспроизводимость автономной версии перед публикацией. В настройках репозитория источник Pages должен быть `GitHub Actions`.

`FB-Autoload.html` — автономная копия для просмотра без сервера. Она собирается из тех же проверенных файлов командой `npm run build:preview`; редактировать её отдельно не нужно. Скрипты и стили разрешаются CSP по хешам, внешние соединения запрещены.

## Ограничения

Это портфолио закрытого приложения, не открытый релиз самого продукта. Отдельная лицензия на производственный код не предоставляется. Контакты автора, ссылки на профиль и название публичного репозитория добавляются после согласования, а не угадываются.
